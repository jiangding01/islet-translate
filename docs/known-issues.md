        4. 显示加载点的段按住视为取消（按「看到的状态取反」统一规则）。

## 3. 渲染与分段的既有取舍

- M2a 分段取舍（原第 5 节 M2a）：
    - 已知取舍（与 FluentRead 相同）：弹性容器里「直接写的文字 + 链接」会被分成两段翻译，行内片段的译文还会成为容器的一个新项，在 `justify-content: space-between` 的容器里可能被推到中间。FluentRead 靠把原文包进一个合成 span 来避免，我们不移动网页节点，暂不做；真机验收时留意。

- M2b 已知限制：
    - **已知限制**：WXT 内容脚本包装层仍会在 `document` 上派发带扩展 ID 的 CustomEvent，已知 ID 的网页可以借它确认扩展存在；`postMessage` 广播已关闭。带 `CSP: sandbox` 头的本地页面实测能正常加载按需模块并翻译，没有回归。

- 「仅看译文」遗留（#35 之后）：视口单位与媒体查询不跟随，接受为已知限制；em 边框/圆角归零等真实反馈再修（详见 `docs/reviews/2026-11-17-translation-only-followups.md`）。
- 产品名被直译（「Sonnet」译成「十四行诗」），属专有名词保护，留给 M4 术语库。
- 按住手势找不到「内部元素被换成相同克隆」的块（既有问题，2026-11-24 审查 #76 时发现，未修）：重扫时块单元按「同类型、同文本」保留旧单元（修复前的 `isCurrent` 同样如此），但旧单元的 `unit.nodes` 仍指向已脱离页面的旧元素；`toggleAt`（`session.ts`）用 `unit.nodes.some((node) => node.contains(hit))` 找单元，按住新元素里的文字时找不到对应段落，追补重扫后仍保留旧单元，这次按住没有反应。以后可让块单元改用 `unit.root.contains(hit)` 判断（run 仍比节点）。

以下 2026-11-24 起记录（来自 Gemini 审查核实，详见 `docs/reviews/2026-11-24-gemini-review-verification.md`）：
- **429 冷却期间页面无提示**：后台进入限流冷却时，Port 协议没有冷却帧，页面上只看到段落迟迟不出译文。提示需要新文案，用户决定先观察、不加，等反馈。
- **LLM 引擎快速滚动时请求积压**：已发出的请求不撤销（`m2-page-translation.md` 5.4），调度器同一调用方内先进先出，新视口的段落要排在已滚走的批次之后，最多等几轮 LLM 批（每轮约 10 s 量级）。有反馈再从两种小改法里选：(a) LLM 引擎下前端批次对齐适配器上限（20 段 / 3000 字），`MAX_IN_FLIGHT` 降到 3–4，改 `session.ts` 几行（推荐）；(b) 对滚出范围、整包尚未开始的请求发 cancel，但前端判断不了是否已开始，误取消会浪费 token。
- **Preact Phase 1（弹窗与设置页换 `preact/compat`）暂不做**：触发条件为 popup 预算余量 < 3 KB，或 M4 设置页设计时预算告急；届时按审查核实文档 4.2 的 spike 验收标准执行，新增依赖需批准。
- ~~**已知限制：AI 整页逐段出现，编号连续但内容错位**~~（#83，`docs/plans/llm-batch-incremental.md`「残余风险」第 1 条）**显示层已由 PR②（#待补）处理**：提前显示前先粗查译文与原文的加权长度，明显对不上就停止这一批的提前显示；整批校验失败（`validation/bad-response`，且这一批多于 1 段）时，后台对已提前显示的段发撤回帧，页面撤下这些译文（同一句话在别处显示的同一份错译、页面内存里的这条记录一并清掉），显示加载点并单段重译。方案与实施记录见 `docs/plans/llm-batch-revoke.md`。缓存规则不变：只有整批校验通过的请求才写缓存。
- ~~**已知限制：AI 整页逐段出现，草稿与终稿不同**~~（#83，同上「残余风险」第 2 条）**显示层已由 PR②（#待补）处理**：判为疑似草稿或与整批解码结果不一致时，整批抛 `bad-response`，已提前显示的段同样撤回重译。只用散文改口（数组后只有文字）时整批解码取到的仍是草稿，会写进缓存，这与改前相同，现有模型输出里没有观察到。
- **已知限制：撤回后仍可能留下的错位译文**（PR②，#待补，`docs/plans/llm-batch-revoke.md`「残余风险」）：
  1. **出错前缀留在页面**：模型合并错位后、整批结束前，输出被截断、中断或超时（包括流正常结束、但数组没写完），而长度对照没有触发时，这批提前显示的段保留，错位前缀留在页面上（不写缓存），要点「显示原文」或刷新。长度对照已触发时，这些结束方式都按整批校验失败处理，已显示的段撤回重译。请求被取消（点「显示原文」、离开页面）时不再发撤回帧。
  2. **后台重启丢帧**：Service Worker 在裁决出来前重启，Port 断开，撤回帧丢失，错位译文留在页面（不写缓存）。
  3. **长度相近的错位**：相邻段长度相近时，长度对照检不出来，只能等整批校验后撤回；用户会看到错译闪现几秒。
- **推理模型内联思维链的剩余缺口**（#75 之后）：终稿已剥离 `</think>` 之前的推理（batch 取第一个、text 取最后一个 `</think>`，理由见审查核实文档 2.1）。流式过滤器 `createThinkFilter` 只扣住以 `<think>` 开头的推理，缺开标签（`推理…</think>译文`）时划词卡片的流式增量会先显示推理文字，终稿再纠正。`<thinking>`、`<reasoning>`、harmony channel 等其他标记不处理；没有 `</think>` 的未闭合思维链不做特殊处理（同修复前，多数情况报 `validation/bad-response`）。都等反馈。
