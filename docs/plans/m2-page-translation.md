## 1. 目标与完成标准

M2 让用户在任意外文网页上「一键得到近乎原生的双语页面」，并能随时完整还原。M0–M2 构成 MVP。

完成标准：

1. 在工具栏面板点「翻译此页」，或按快捷键（Mac `⌃⇧A`，其他系统见 5.1）：视口内的段落先出译文，Google 引擎首批 ≤ 800ms；往下滚动时继续按需翻译。
2. 译文继承网页的字体、字号、颜色和行距，只用「略淡」等层级区分；不改变原文，不挤压版面。
3. 「双语 / 仅译文 / 原文」随时切换，正在读的那一行不跳走；切回原文后 DOM 与翻译前一致（没有残留节点、属性和样式）。
4. 页面后续加载的内容（无限滚动、展开评论）自动翻译；框架重新渲染把译文冲掉时自动补回。
5. 「总是翻译此站」：打开该站点的外文页面时自动翻译。
6. 出错时安静地说明：单段失败在原地给出「重试」；引擎级错误（密钥、额度、本地服务拒绝）只在工具栏面板和图标小点上提示，并给一键「这次先用 Google 翻译」。
7. 关页或停止后，在途请求 ≤ 1 秒内中止；Service Worker 被回收后自动重连并续译未完成的段落。
8. 内容脚本 gzip ≤ 20KB；在 4 倍 CPU 降速下，翻译过程中单个主线程任务 ≤ 8ms（分片执行），宿主 LCP 退化 ≤ 50ms。

## 2. 不做的事（M2 范围外）

- **灵岛**（贴边小点、竖排灵岛、弹簧形变、三种停靠、碰撞避让）：放在 **M2b**，单独一个 PR，见第 11 节。M2a 合并后，用户通过工具栏面板和快捷键就能完整使用整页翻译。
- SPA 路由换代、跨源 iframe、open Shadow DOM 扫描、10 个站点的专属 adapter：final-plan 把「动态页」放在 M3。M2 只做通用的 MutationObserver（新增内容、被框架冲掉的译文），不 hook `history`。
- 右键菜单、划词、悬停译段、输入翻译：M3。
- LLM 整页流式输出：final-plan 明确整页不流式（避免布局抖动），段落整体到达后一次插入。
- 增强级动效（高度展开）：`ui-isle-direction` 第 5.6 节允许按性能实测决定。M2 只做基础级（透明度加轻微模糊），省掉逐帧布局计算。
- 工具栏图标改成单色字形：需要新的图标资产和设计确认。M2a 只在现有图标上叠加状态小点。
- 站点规则（include / exclude 选择器）：M3 随 adapter 一起做。M2 用通用规则，并支持网页自带的 `translate="no"` 和 `.notranslate`。

## 4. 总体结构（M2a）

```
 工具栏面板 (popup) ──tabs.sendMessage──▶ 内容脚本 content.ts（无 React，≤20KB）
        │  page.getState / start / stop / setMode / retryFailed        │
        │                                                              ├─ session.ts   会话：状态机、epoch、重连重发
 Background SW                                                         ├─ discover.ts  扫描：分片遍历 → 翻译单元
  ├─ commands: ⌃⇧A ──tabs.sendMessage(page.toggle)──▶                  ├─ segment.ts   单元 → 文本（含行内占位符）
  ├─ page.status ◀──sendMessage── 内容脚本（更新图标小点）              ├─ viewport.ts  IntersectionObserver + 优先级队列
  ├─ siteMemory 写入（只接受扩展页面）                                  ├─ render.ts    插入译文、样式、动效、失败提示
  └─ Port et-translate ◀────────── 内容脚本（翻译请求，M1 已有）        ├─ restore.ts   完整还原
                                                                       ├─ mutations.ts 新内容与被冲掉的译文
                                                                       └─ anchor.ts    阅读位置锚定
 storage.local: config（后台唯一写入）· siteMemory（后台写入，内容脚本只读）· secrets（只有后台读）
```

数据单向流动：内容脚本只发翻译请求、读配置和站点记忆、上报状态；所有写入都经过后台，并校验发送方。没有环。

## 5. 关键设计

### 5.1 触发与会话

- **入口**：
  - 工具栏面板「翻译此页」；
  - 快捷键：manifest `commands` 里的 `translate-page`。Mac 用 `MacCtrl+Shift+A`（即 `⌃⇧A`）；Windows 和 Linux 不能用 `Ctrl+Shift+A`（Chrome 自带的「搜索标签页」会让扩展的声明静默失效），改用 `Alt+A`（Chrome 似乎把 `Alt+Shift+A` 用于聚焦不活跃的对话框，也要避开；Windows 上左 Alt 加字母不输出字符，AltGr 被浏览器视为 `Ctrl+Alt`，不会误触）。手工验收时用 `commands.getAll()` 确认各平台都实际分配到了快捷键；没有分配到时，面板显示「设置快捷键」并链接到 `chrome://extensions/shortcuts`。用户可以在那里自行修改；
  - 站点记忆「总是翻译此站」。
  
  三者调用内容脚本的同一个 `toggle()`。界面上显示的快捷键从 `commands.getAll()` 读取实际值，不写死。
- **会话状态机**：`idle → running ⇄ (bilingual | translation-only) → restoring → idle`。
  - 每次 `start` 生成新的 `epoch`。所有回调先核对 epoch，旧 epoch 的结果一律丢弃；HANDOFF 要求的「本地防串写」由此实现。
  - `stop` 的顺序：先递增 epoch，再 `cancelAll()`，再断开各个观察器，最后还原。还原是幂等的。
- **Port 会话**：一个页面会话复用一个 Port 客户端（M1 的 `createPortClient`）。断连时（SW 被回收），在途请求以 `network/port-disconnected` 结束；会话把这些单元重新放回队列，按退避（0.5s、1s、2s，最多 3 次）重发，已完成的段会直接命中缓存。关页时 Port 断开，后台 M1 已经实现「断开即中止该 Port 的全部在途请求」。
- **扩展更新或重载**：旧的内容脚本会失去和扩展的连接（Port 报 `internal/context-invalidated`，或任何扩展 API 抛出 context invalidated）。这时静默收场：停止派发，断开所有观察器，保留已经插入的译文，不显示任何失败提示。用户刷新网页后就是新版本。
- **一次性的引擎替换**：面板上的「这次先用 Google 翻译」只作用于当前会话。为此给 `TranslateRequest` 增加可选字段 `engine?: Engine`，后台优先使用它；不写入配置。

### 5.2 发现翻译单元（discover.ts）

借鉴 FluentRead 的思路：后序遍历，以「叶子块」为单位，分片执行。

- **遍历**：用显式栈做后序遍历，范围是 `document.body`。每处理 64 个元素检查一次耗时，超过 8ms 就让出主线程：优先用 `scheduler.yield()`，不支持时退回 `setTimeout(0)`。
- **块与行内的判定**：
  - 语义块标签（`p, li, h1–h6, blockquote, dd, dt, td, th, figcaption, caption, summary`）一律视为块边界。
  - 语义行内标签（`a, span, b, strong, i, em, u, mark, s, small, sub, sup, abbr, cite, q, time, label`）一律视为行内。
  - 其他元素（`div`、`section`、自定义元素等）看计算样式的 `display`：以 `inline` 开头的是行内，其余是块。
  - **flex 和 grid 容器的子元素例外**：浏览器会把它们的 `display` 一律算成块（块化），所以父元素是 `flex`、`grid`、`inline-flex` 或 `inline-grid` 时，不看子元素的计算样式，只按上面的语义标签判定；不在语义清单里的子元素，按它自己的内联 `style.display` 判定，没有设置就当行内。这样「作者 · 3 小时前 · 5 条评论」这类 flex 元信息行会成为一个单元，不会被拆碎。
  - `getComputedStyle` 只对不在语义清单里的元素和它们的父元素调用，结果按元素缓存在 `WeakMap` 里。
- **单元**：
  - 叶子块：一个块元素，它的子节点里没有可读的块元素。
  - 行内片段：混合块里（文字和块子元素混排），连续的文字和行内子元素组成一段，块子元素是分隔。
  
  单元记录根元素、它包含的节点范围，以及源文摘要（`sourceDigest` 用 FNV-1a，只用于比对，不用于缓存键）。
- **跳过**：
  - 标签：`script, style, noscript, template, iframe, svg, canvas, video, audio, math, input, textarea, select, button, code, kbd, samp, pre`；
  - 属性和类：`[contenteditable]`、`[translate="no"]`、`.notranslate`、`[aria-hidden="true"]`、`[hidden]`、`[inert]`；
  - 导航与控件：`nav`、`[role=navigation|button|menu|tab|toolbar]`；
  - 我们自己插入的节点：`et-tr`，以及带 `data-et` 属性的节点；
  - 其他翻译插件插入的节点：沉浸式翻译的 `immersive-translate-target-wrapper`。
- **文本过滤**：去掉首尾空白后至少要有 2 个字母（Unicode `\p{L}`），且整段不能只是 URL、邮箱、`@用户名`、`#话题`、数字加单位、文件名或代码标识符；单元超过 5000 字符时跳过。整页语言等于目标语言时，入口提示「这一页已经是…」（M1 面板已有），面板同时保留「仍然翻译」按钮与目标语言选择（见 `popup-translate-anyway.md`）；单段与目标语言相同时由后台判定（M1 的 `same-language`），内容脚本不渲染。
- **不可见的内容照常注册**：发现阶段不按 `display:none` 或 `visibility:hidden` 跳过。标签页、折叠面板、「显示更多」常用类名切换显隐，不会触发 DOM 结构变化。这些单元照常注册到 IntersectionObserver：隐藏时不相交，显示出来后观察器自然回调，再翻译。这也省掉了一轮全量的样式计算。
- **深度保护**：祖先链超过 512 层的子树跳过，防止恶意构造的超深 DOM 卡死页面。

### 5.3 文本与行内标记（segment.ts）

整句翻译，保证译文质量；行内标记（链接、加粗、行内代码）尽量还原，还原不了就整段退回纯文本，不影响原文。

- **发送格式**：单元的文本按 DOM 顺序拼接。可还原的行内元素（`a, b, strong, i, em, u, mark, s, small, sub, sup, code, span[有文字]`）用编号标记包住，自闭合的（`img, br`、行内 `code` 当整体保护时）用编号占位符。编号标记的具体写法见 5.3.1。
- **校验**：译文里每个编号必须恰好出现一次，成对标记的开闭顺序要合法（不交叉），不能出现源文里没有的编号。任何一项不满足，这一段就整段渲染成纯文本译文。这就是 final-plan 写的「占位符丢失整块回退」，只不过回退到纯文本译文，而不是原文。
- **还原**：
  - 译文里的标记映射回源节点：对源元素做浅克隆，内容换成译文片段。克隆保留源元素的属性（包括 `class`、`style`，强调色、链接样式才能保住），只删掉 `on*` 事件属性、`srcdoc`、`formaction` 以及 `id`（避免页面出现重复 id）。
  - 链接用克隆后元素的 `.protocol` 校验（浏览器已按页面地址解析好相对链接，所以 `/wiki/Foo` 这类站内链接正常保留），只允许 `http:`、`https:`、`mailto:`，其他（如 `javascript:`）去掉 `href`。
  - 所有属性值都来自页面自己的源元素；引擎输出只决定标记的编号和顺序，永远不贡献属性，也永远不会被当成 HTML 解析，只用 `textContent` 和克隆节点组装。
  - 自闭合占位符还原为源节点的克隆，比如图标 `img`。
- **与源文冲突**：标签默认写成 `<t0>`。如果源文里本身就出现了 `<t` 加数字这样的文本，就从固定的字母前缀序列 `t, u, w, z, tt, uu` 里按顺序选第一个没在源文中出现过的。选择结果只由源文决定，不随机：同一段在任何时候生成的发送文本逐字节相同，SW 重连后的重发和以后再访问同一页面都能命中缓存（M1 的缓存键包含发送文本）。六个前缀都冲突时，这一段不带标记，直接按纯文本翻译。

#### 5.3.1 标记写法（两种引擎相同）

- **统一写法**：成对标签 `<t0>…</t0>`，自闭合 `<t2/>`；冲突时换前缀（`<u0>`、`<w0>` 等），始终是「字母加数字」的形式。
- **Google**：以纯文本模式发送（M1 适配器原样发送，不开 `format=html`），不做 HTML 转义，也不用解码实体。附录 B 的实测表明，这种写法的标签在纯文本模式下能保留，并随语序调整正确移动。
- **Google 丢标签时用 HTML 模式重试一次**（2026-11-17 增补，`src/lib/translate/providers/google-html.ts`）：语序大幅调整时，纯文本模式会把标签整个丢掉（附录 B 第三组）。适配器按与 `restoreTranslation` 相同的规则检查每条译文的标签；不完好的条目合成一个 `format=html` 请求再发一次（同样受 5000 字上限约束，放不下的不重试）。写法：最外层成对标签 `<a id="t0">`，内层 `<b id="t1">`（`<a>` 套 `<a>` 会被拆平），自闭合 `<code id="t2"></code>`；文本转义 `& < >`。返回结果只用正则加栈转回 `<t0>…</t0>`、解码实体，不当 HTML 解析；转回后标签仍不完好，或只是原样回显原文时，保留第一次的译文。重试失败（网络错误、429）同样保留第一次的译文，只有取消请求时才报错。修好的译文照常写缓存；已缓存的坏译文不会自动失效。
- **LLM**：M1 的提示词增加一句通用说明「保留形如 `<字母+数字>…</字母+数字>` 和 `<字母+数字/>` 的标签及其包裹关系，不要翻译或改动标签本身」。这句说明会进入提示词摘要，因此也进入缓存键。
- **两种引擎都一样**：校验不通过就整段退回纯文本译文。

### 5.4 视口优先与批次（viewport.ts）

- **观察**：每个单元的根元素注册到一个 IntersectionObserver，`rootMargin: '1000px 0px'`（HANDOFF 已定）。进入范围就入队；离开时如果还没发出请求，就移出队列；已经在途的请求不撤销。观察器回调只做入队，排序和发送都留给 flush；一次回调的条目超过 500 条时，入队也分片执行（万段级页面首次回调会一次送来上万条）。
- **优先级**：队列在 flush 时一次性读取所有候选的位置（先读后写，避免强制同步布局），按「视口内 > 视口下方 > 视口上方」排序，同一档内按文档顺序。滚动期间只发视口内的单元。
- **批次**：flush 用 50ms 防抖，每批最多 50 个单元、8000 字符，作为一个 `TranslateRequest` 经 Port 发出；后台 M1 的调度器再按各个引擎的限制拆分、合并和排队。每个 Port 最多 8 个在途请求，这是 M1 的约定，内容脚本会遵守。
- **首屏**：`start` 后第一次 flush 不等防抖，视口内的单元立即发出。

### 5.5 渲染与样式（render.ts）

- **插入位置**：
  - 双语：在单元根元素的**末尾**插入子元素 `<et-tr lang="{目标语言}" translate="no" dir="auto">`，`display:block`，`margin-top: .25em`。作为子元素，它会继承根元素的字体、字号、颜色和行距。
  - 行内片段：在片段最后一个节点之后插入，`display:inline`，前面加一个空格。
  - **单元根本身是 flex 或 grid 容器**（GitHub 带锚点图标的标题、卡片页脚）：块级的 `et-tr` 会变成一个 flex 项目，和原文挤在同一行。这时改走行内插入：插在最后一个含文字的子元素内部的末尾；如果最后的文字是裸文本节点，就紧跟在它后面插入行内的 `et-tr`，连续的行内内容会落进同一个匿名 flex 项目，布局保持正确。
  - 不改写任何宿主文本节点，也不移动宿主节点。这是 FluentRead 踩过的坑：改写或移动框架管理的节点，会和 React 这类框架互相覆盖，形成死循环。
- **仅译文**：
  - 根元素加属性 `data-et-only`，用样式隐藏原文：元素子节点 `display:none`；裸文本节点用根元素 `font-size:0` 隐藏，`et-tr` 再设回原来的字号（插入时读一次计算样式并记下）。
  - **钉住间距**：段落的外边距和内边距通常用 `em` 设置，跟着字号变成 0，整页段落会挤在一起。所以进入仅译文前，先读取根元素计算后的 `margin` 和 `padding`（像素值），用内联样式钉住。尺寸同理：`max-width: 80ch` 这类写法会变成 0，译文被挤成一行一个字，所以 `min/max-width`、`min/max-height`、`flex-basis`、`text-indent` 也按计算值钉住；`width`、`height` 的 `getComputedStyle` 值对 `auto` 也返回像素，改读 Typed OM（`computedStyleMap`），只钉显式长度。值为关键字（`auto`、`none`）的不钉，留给宿主样式。钉住前记下原来的 `style` 属性；还原时，整串仍是钉完后的值就逐字节还原（原来没有就删属性），网页改过则先写回原样式、再重放网页在这期间的改动，详见 `translation-only-style-restore.md`。
  - 只改属性和我们自己的节点，不移动宿主节点。
  - 行内片段在仅译文模式下保持双语显示，不隐藏原文（避免移动宿主节点）。
  - 含链接、但行内标记没能还原、退回了纯文本的段落（Google 会先用 HTML 模式重试一次，见 5.3.1），仅译文模式下照常隐藏原文，代价是这一段的链接在仅译文下点不到，切回双语即可找回。（2026-11-17 修订：原规则是这类段落保持双语，但用户把「仅译文里露出原文」视为 bug。claude.dev 博客首段实测，Google 把 `<t0>…</t0>` 整个丢掉，链接对应的文字在中文里也不再连续，无法把链接放回译文。见附录 C 第 8 条。）
  - 整段文字都包在同一个可还原的行内元素里（整段就是一个链接，常见于卡片标题、列表项）时，即使退回纯文本，也把整段译文包进这个元素的克隆，链接照常可用。
  - 已知副作用：仅译文模式下全选复制，字号为 0 的原文仍会被复制。手工验收时记录现状，M2 不处理。
  - 已知限制（2026-11-18）：仅译文时根元素上用视口单位（vw/vh）或按媒体查询切换的尺寸会被钉成切换当时的像素，调整窗口后不跟随；切回双语即恢复。`auto` 外边距与百分比内外边距不受影响（Typed OM 保留原值）。
- **4 种样式**（琥珀版，原型确认后定稿）：无装饰、**淡化（默认）**、下划线、高亮。
  - 默认改为「淡化」，透明度 0.72，依据是最高 UI 原则：译文像原生内容，只靠层级区分。旧规范的默认是「下划线」。
  - 下划线和高亮的颜色按宿主亮暗二选一：从单元根元素往上最多找 8 层，取第一个不透明的背景色，算亮度，结果按容器缓存。
- **样式注入**：在 `document.head` 插入一个 `<style data-et>`，选择器写成 `et-tr[data-et-s][data-et-s]` 提高优先级；只设置 `display, margin, text-decoration, background, opacity, font-size` 这几类属性。还原时删除这个元素。
- **截断容器**：卡片和摘要常用多行截断（`-webkit-line-clamp`），译文插进去会被截掉。插入前检查根元素和它往上 2 层：有 `-webkit-line-clamp` 时，给该元素加属性 `data-et-unclamp`，样式里对它解除截断（`-webkit-line-clamp: unset`）。卡片会因此变高，这是看到译文的必要代价；还原时去掉属性。`max-height` 加 `overflow:hidden` 的组合不处理：它更常见于轮播、图片裁剪和折叠动画，盲目解除会改坏网页组件。个别卡片的译文因此被截时，双语模式下原文仍然完整。

### 5.6 动效与阅读位置（render.ts、anchor.ts）

- **出现**：只给视口内的单元做动效：`opacity 0→1` 加 `filter: blur(2px)→0`，200ms。同一批内依次错开 30ms，最多错开 6 段，其余同时出现。视口外的单元直接插入，不做动效。
- **消失**（还原或切到原文）：视口内的译文先淡出 140ms，然后在**同一帧**里一次性移除全部 `et-tr` 和属性，视口外的直接移除。
- **双语与仅译文切换**：先锚定，再做 120ms 交叉淡化。
- **阅读位置锚定**：
  - 插入译文时依靠浏览器原生的滚动锚定（CSS `overflow-anchor`，Chrome 默认开启），视口上方插入内容时浏览器会自动修正。实测（2026-11-18，见 `paragraph-loading.md`）：视口上方插入完全补偿；视口内插入只保住视口顶部那段，下方正在看的段落会被推下。
  - 模式切换和还原时，原生锚定选到的锚点可能正好是被隐藏的元素，所以自己做：取视口中线处的元素作为锚点，记下它的位置；变化后补回差值。补回作用在锚点最近的可滚动祖先上（`overflow` 可滚动且内容超出），很多文档站和网页应用的正文在内层容器里滚动；找不到时才滚动 window。
- **减少动态效果**：开启 `prefers-reduced-motion` 时，出现和消失都直接完成，只保留不超过 120ms 的透明度变化，没有模糊。
- **实现约束（2026-11-14 用户要求动效丝滑，作为验收标准）**：
  - 只动合成器可处理的属性（`opacity`、`filter`），动画期间不读布局；`will-change` 只在动画进行时设置，结束即撤。
  - 用 Web Animations API（`element.animate()`），不靠切换 CSS 类：每段动画可以随时打断和反向。例如淡入中途点了「显示原文」，从当前透明度直接淡出，不先跳满；等全部动画的 `finished` 后，在同一帧里一次性移除节点。
  - 同一批插入在一个 `requestAnimationFrame` 里完成写入，动画在下一帧开始，避免插入和动画抢同一帧。
  - 模式切换的 120ms 交叉淡化拆成前 60ms 淡出单元根元素、切换属性、后 60ms 淡入，锚定在切换前后各做一次。
  - 验收：4 倍 CPU 降速下录 Performance，翻译、滚动续译、模式切换、还原过程中没有超过 50ms 的长任务，动画帧率保持 60fps。

### 5.7 动态内容（mutations.ts）

- **观察**：一个 MutationObserver，选项是 `childList + subtree + characterData`，不观察属性，降低大页面的开销。回调先过滤掉我们自己的写入：目标是 `et-tr` 或在它里面、带 `data-et` 的属性变化。
- **新增内容**：把新增子树的根合并成「脏根」集合，300ms 防抖后用 5.2 的分片扫描处理。脏根超过 32 个时直接合并成 `body`，冷却时间递增（1 秒、2 秒、4 秒封顶，安静 10 秒后复位），防止 X 这类页面持续触发整页重扫。重扫时，摘要没变、上一轮已处理过的单元直接跳过。
- **被冲掉的译文**：会话里保存「单元 → 译文」的映射。框架重新渲染时如果移除了 `et-tr`，或者换掉了整个根元素，下一轮扫描遇到源文摘要相同的单元，就直接用已有译文重新插入，不发请求。
- **源文变了**：已翻译单元的源文摘要变化时，移除旧译文，重新入队。
- **受保护区域**：重扫前先检查被改动元素到 `body` 之间的祖先，命中受保护规则（编辑区、`translate="no"`、`notranslate`、导航等，临时隐藏三项除外）就跳过；见 `rescan-protected-areas.md`。
- **防死循环**：按 `sourceDigest` 记录最近 10 秒内的重插次数，超过 3 次就不再处理这段文字，并在控制台输出一次警告。按摘要而不是按元素计数：虚拟列表每次重新挂载都是新元素，按元素计数会永远归零。

### 5.8 失败与降级

| 类型 | 判定 | 表现 |
| --- | --- | --- |
| 单段失败 | 该单元的结果是错误，且错误码不在下面两类里 | `et-tr` 的位置显示一行小字：「未译出 · 重试」，用珊瑚色，12px，没有背景。点「重试」只重发这一段 |
| 引擎级错误 | `config/*`、`provider/unauthorized`、`provider/quota-exceeded`、`provider/local-origin-rejected` | 暂停派发新的请求，不在每段上显示；工具栏图标显示珊瑚色小点；面板说明原因，给出「去设置」和「这次先用 Google 翻译」 |
| 限流 | `rate-limit/*`（M1 调度器已退避重试） | 重试用尽后按单段失败处理 |
| 断连 | `network/port-disconnected` | 按 5.1 自动重连重发，不显示 |
| 扩展更新或重载 | `internal/context-invalidated` | 按 5.1 静默收场，保留已有译文，不显示 |
| 请求级错误 | 整个请求返回一个错误帧，而不是逐段结果（如 `rate-limit/port-busy`、`validation/payload-too-large`、读取配置失败） | 永远不直接变成段内失败提示：限流和断连类，整批放回队列，按退避重发；配置类按引擎级错误处理；`payload-too-large` 说明批次计算有误，这一批对半拆开重发 |

面板提供「重试全部失败（n）」。失败计数通过 `page.getState` 返回给面板。

### 5.9 站点记忆

- **存储**：新增键 `storage.local["siteMemory"] = { [origin]: { always: boolean } }`。这和 `config` 分开存放，是 final-plan 第 3 节定的。
- **写入**：只能由后台写入，消息是 `site.setAlways(origin, always)`，只接受扩展页面（面板、设置页）发出，和 M1 的配置写入校验相同。后台写入前校验 `origin`：必须满足 `new URL(origin).origin === origin`，且协议是 `http:` 或 `https:`，否则拒绝（这也挡住了 `__proto__`、空串、带路径的值）。读取时只认自有键（`Object.hasOwn`），这是 M1 修复「键名叫 `constructor` 清空设置」时得出的做法。内容脚本可以直接读这个键，但没有写入路径。
- **自动翻译**：内容脚本在 `document_idle` 读取站点记忆。如果该站点设了「总是翻译」，且页面语言不是目标语言（看 `<html lang>`；没有声明时，用 `chrome.i18n.detectLanguage` 检测前 2000 个字符），就自动 `start`。

### 5.10 工具栏面板与图标

- **面板**：沿用 M1 的布局，接上真实能力（原型确认后实现）：
  - 外文页：主按钮「翻译此页 ⌃⇧A」可用，点击后面板自动关闭（`window.close()`），焦点回到网页。
  - 翻译中：显示细进度线，按钮变成「停止并显示原文」。
  - 已翻译：显示「双语 / 仅译文」分段切换、「显示原文」，有失败时显示「n 段没有译出 · 重试」。
  - 「总是翻译此站」开关。
  - 默认引擎缺密钥时，主按钮变成「这次先用 Google 翻译」。
- **图标状态点**：
  - 内容脚本在状态变化时发消息 `page.status`，内容是 `idle | running | done | error`。
  - 后台用 `OffscreenCanvas` 在现有图标上画一个 6px 的小点：翻译中和已翻译用琥珀色，有失败用珊瑚色，idle 不画。再按标签页调用 `action.setIcon({ tabId, imageData })`。
  - 标签页导航或关闭时清除。

### 5.11 配置与消息协议增量

- **配置**：新增 `page.style`，取值 `'plain' | 'faded' | 'underline' | 'highlight'`，默认 `'faded'`；新增 `page.mode`，取值 `'bilingual' | 'translation'`，默认 `'bilingual'`，作为新会话的初始模式。按 M0 的约定，在 schema 和默认值里追加，不提升版本号。设置页「通用」增加「译文样式」，带即时预览（原型确认后实现）。
- **一次性消息**：
  - 面板 → 内容脚本：`page.getState`、`page.start`、`page.stop`、`page.setMode`、`page.retryFailed`；
  - 后台 → 内容脚本：`page.toggle`，来自快捷键；
  - 内容脚本 → 后台：`page.status`；
  - 扩展页面 → 后台：`site.setAlways`。
  
  `page.*` 的处理在内容脚本里，只认扩展自己发来的消息，这一点由浏览器保证，网页无法调用。
- **Port**：`TranslateRequest` 增加 `engine?: Engine`，见 5.1。
- **manifest**：新增 `commands.translate-page`，不需要新增权限。`action.setIcon` 不需要权限。

### 5.12 性能预算

| 项 | 预算 | 手段 |
| --- | --- | --- |
| 内容脚本 | gzip ≤ 20KB | 不用 React；`check:size` 卡住 |
| 主线程单个任务 | ≤ 8ms | 扫描分片、先读后写、批量写 DOM |
| 插入译文 | 每帧一批，每批 ≤ 4ms | 用 rAF 合并写入 |
| 内容脚本内存 | ≤ 15MB/标签页 | 只缓存「单元 → 译文」，随会话释放 |
| 宿主 LCP | 退化 ≤ 50ms | `document_idle` 注入，未唤起时只读一次站点记忆，不扫描 |

**零痕迹**：未唤起翻译时，内容脚本不扫描、不观察、不插入任何节点，只注册消息处理并读一次站点记忆。

## 6. 差异化（针对竞品痛点）

| 竞品痛点 | M2 的做法 |
| --- | --- |
| 每个页面默认挂浮球，要逐站关闭 | 默认零痕迹，只在用户唤起或站点记忆为「总是翻译」时才动；M2a 甚至不在页面上放入口 |
| 大页面卡顿 | 只译视口附近；扫描分片；内容脚本不带 React；视口外直接插入、不做动效；长页面用 `content-visibility` |
| 排版错乱、和网页框架打架 | 译文作为子元素继承宿主样式；不改写、不移动宿主节点；还原逐项撤销；被框架冲掉后自动补回，并防止死循环 |
| 阅读时页面跳动 | 依靠原生滚动锚定，模式切换和还原时再显式锚定；整页不流式；每段只发生一次布局变化 |
| 429 或引擎失效只能手动换 | 引擎级错误只提示一次，面板一键「这次先用 Google 翻译」（只作用于当前会话）；调度器自动退避 |
| 免费额度不透明、订阅弹窗 | 无账户、无额度，默认免费引擎，失败原因说清楚 |

## 7. 相对 final-plan 的偏离（需要批准）

1. **MutationObserver 从 M3 提前到 M2**：只做「新增内容」和「被框架冲掉的译文」两件事。没有它，无限滚动和展开评论都翻译不到，整页翻译在主流网站上基本不可用。SPA 路由换代、iframe、Shadow DOM 仍留在 M3。
2. **默认样式从「下划线」改为「淡化」**：依据是 2026-11-14 确立的最高 UI 原则。
3. **内容脚本不拆 core/ui 两层**：M2a 没有 React 界面，单个内容脚本就能满足 ≤20KB。拆分等 M3 引入划词卡片时再做。
4. **体积门禁继续用自写脚本**，不用 size-limit，沿用 M0 的偏离。
5. **工具栏图标只叠加状态点**，单色字形延后（需要设计资产）。

## 8. 风险与前提

1. **Google 对标签的保留只测了一句话**（中）：附录 B 证明写法可行，但大量文本下不能保证次次保留。校验不通过的段落整段退回纯文本；仅译文模式下这类段落照常隐藏原文，段内链接在仅译文下暂时点不到（5.5），整段就是一个链接的情况照常保留链接。手工验收时在 MDN、Wikipedia 上统计退回纯文本的比例；超过 10% 时，M3 再评估改用 `format=html`（附录 B 第二组实测表明它同样可行，代价是要做转义和实体解码）。2026-11-17 已先做有限重试：只对标签丢失的条目用 HTML 模式再请求一次（5.3.1），没有全面切换。
2. **前提（手工验收时实测）**：快捷键在 Windows 和 Linux 上实际分配到 `Alt+A`。没有分配到时，面板引导用户去 `chrome://extensions/shortcuts` 设置（5.1），不阻塞其他功能。
3. **框架冲突**（中）：仅译文模式的 `font-size:0` 手法，遇到宿主给文字设置了 `!important` 字号会失效，表现为原文和译文同时显示。可以接受，用户切回双语即可。10 站手测会覆盖。
4. **SW 回收**（中）：靠重连重发兜底；Port 消息本身也会刷新 SW 的空闲计时（final-plan 风险 5）。手工验收会在 `chrome://serviceworker-internals` 停掉 SW 实测。
5. **超大页面**（中）：分片扫描加 1000px 视口范围，能限制单次工作量；手测里包含一个万段级别的页面。
6. **其他翻译插件同时开着**（低）：跳过对方插入的节点；如果双方同时翻译同一段，结果以先插入的为准。不做额外协调。

  - 分段：标记编号、nonce 冲突、同一单元两次生成的发送文本逐字节相同、校验（缺失、重复、交叉、多出）、退回纯文本、相对链接保留、`javascript:` 链接被去掉、`on*` 属性被删除。

## 附录 B：Google 标记保留实测

2026-11-14，用户在终端用 curl 执行，接口与 M1 适配器相同（`POST translate_a/t?client=gtx&sl=en&tl=zh-CN`）。源句：「Read [the full guide] before you [install] it, then run [x] again.」，方括号处是标记。

| 写法 | 模式 | 结果 |
| --- | --- | --- |
| `<b0>…</b0>`、`<i1>…</i1>`、`<c2/>` | 纯文本 | 全部保留，随语序调整正确移动：「在<i1>安装</i1>之前阅读<b0>完整指南</b0>，然后再次运行<c2/>。」 |
| `{0}…{/0}`、`{2}` | 纯文本 | 全部保留（`{2}` 前多出一个空格） |
| `[0]…[/0]`、`[2]` | 纯文本 | 全部保留 |
| `⟦0⟧…⟦/0⟧`、`⟦2⟧` | 纯文本 | 全部保留 |
| 真实 HTML：`<a id="0">`、`<b id="1">`、`<code id="2">` | `format=html` | 全部保留，属性不变，`<code>` 里的 `npm start` 没有被翻译 |
| `<a href="#">`、`&amp;`、`<em>` | `format=html` | 标签保留，`&amp;` 被当作「&」理解并译成「并」 |

结论：选用「字母加数字」的标签、纯文本模式（5.3.1）。`format=html` 作为备选，见第 8 节风险 1。

**第三组（2026-11-17，用户在终端用 curl 执行）**：claude.dev 博客 verification 一文首段，语序大幅调整（written and reviewed by Claude → 由 Claude 编写和审查）。

| 写法 | 模式 | 结果 |
| --- | --- | --- |
| `…is written and <t0>reviewed by Claude</t0>. …` | 纯文本 | 标签整个丢掉：「……都是由 Claude 编写和审查的。……」 |
| `…is written and <a id="0">reviewed by Claude</a>. …` | `format=html` | 标签保留并移到对应短语：「……都是<a id="0">由 Claude 编写和审查的</a>。……」 |
| `<a id="t0">the <a id="t1">full</a> guide</a> … <img id="t2">` | `format=html` | 嵌套的 `<a>` 被拆成两个并列的 `<a>`；`<img>` 保留 |
| `<a id="t0">the <b id="t1">full</b> guide</a> … <code id="t2"></code>` | `format=html` | 嵌套保留：「<a id="t0"><b id="t1">完整</b>指南</a><code id="t2"></code>」；空 `<code>` 原样保留 |

结论：Google 丢标签时用 HTML 模式重试，最外层用 `<a>`、内层用 `<b>`、自闭合用空 `<code>`（5.3.1）。
