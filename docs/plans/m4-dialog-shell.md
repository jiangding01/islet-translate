# 设置页对话框收敛：共用 `DialogShell`，顺带修可访问性细节

> 状态：2026-11-26 用户批准方案并实现。来源：`docs/plans/m4-settings-redesign.md` 审查记录里的两条后续项（对话框重复代码、沿用下来的可访问性问题）。

## 起因
「添加服务」「添加/编辑风格」「添加/编辑术语」三个对话框各有一份几乎相同的骨架，约 60 行逐字重复：
- 打开和关闭的 effect；
- transformOrigin 的计算，以及 `DIALOG_WIDTH`、`DIALOG_TOP` 常量；
- dialog 的 onClick 和 onCancel；
- 页头的关闭按钮；
- 底部的错误行。

表单布局也有两套：`.dialogBody/.dialogField` 和 `.formGrid/.formRow`。翻译服务页还留着内联 SVG。

## 做法
- 新增 `src/entrypoints/options/DialogShell.tsx`，负责：
  - 打开和关闭：`onOpen` 用 `useEffectEvent`，打开前由页面重置草稿；打开后聚焦 `initialFocus`；
  - transformOrigin 计算；
  - 页头（标题、副标题、关闭按钮）；
  - `<form noValidate>`；
  - 底部状态行，以及「取消」和主按钮。
- 三个对话框只保留各自的草稿、校验、提交逻辑和字段。
- 表单布局统一用 `.formGrid`、`.formRow`：
  - 「添加服务」的预设 chips 用新类 `.formWide`，横跨两列；
  - 删除 `.dialogBody`、`.dialogField` 两个类。
- 图标：翻译服务页的加号改用 `PlusIcon`，添加服务对话框的关闭按钮改用 `CloseIcon`（由 `DialogShell` 提供）。

## 可访问性与交互修复（三个对话框一起生效）
- **`role=alert` 常驻**：底部状态行里一直挂着一个 alert 节点，只替换文字。「添加时浏览器会询问…」的提示放在 alert 外面，不会被当成报错播报。
- **点遮罩关闭**：只有 pointerdown 和 click 都落在 dialog 元素本身（遮罩）上时才关闭。在输入框里按下、拖选文字后在遮罩上松手，click 会落到两者的共同祖先 dialog 上，以前会误关对话框。
- **busy 时的 Esc**：busy 期间在 `document` 的捕获阶段就拦下 Esc 的 keydown。原因有两层：
  - Chrome 只允许页面在没有用户激活的情况下拦截一次 `cancel`，第二次 Esc 照样会关闭对话框；
  - 保存时「保存」按钮被禁用，焦点有时会离开对话框，所以监听不能挂在 dialog 上。
- **`noValidate`**：不再弹出浏览器原生的 required 气泡，必填提示仍按「输入过又清空」显示。`required` 属性保留，供读屏读出「必填」。
- **迟到的 `close` 事件**（e2e 中发现，旧代码也有）：原生 `close` 事件不是同步派发的。关闭后立刻再打开，上一次关闭的事件可能落在新打开的对话框上，把它又关掉。现在只有对话框确实已关闭时，才把事件转给页面。
  - 前台页面上这个窗口不到一帧，用户基本碰不到；页面不出帧时（e2e 的扩展页、被节流的后台页）就会稳定复现。
  - 这条属于健壮性修复，没有写进 CHANGELOG。
- **焦点**：
  - 术语库：后台判重被拒后，焦点移到原文输入框；
  - 添加服务：接口地址无效被拒后，焦点移到地址输入框。

  先用 `flushSync` 渲染出带 `aria-describedby` 的提示，再移焦点，读屏会连同提示一起读出。添加服务的地址错误以前没有关联到输入框，这次一并补上。

## 不做
- 不新增文案和开关。
- 「添加服务」的模型字段不加必填提示：没填模型时「添加」按钮本来就不可用，加提示需要新文案。
- 「添加服务」的接口地址在失焦时校验，提示出现时会把按钮往下推，与 #96 修过的「取消要点两次」是同一类问题。保持现状，列为后续项。

## 验证
- **组件测试**：
  - 新增 `dialog-shell.test.ts`，覆盖：打开时重置一次草稿并聚焦；alert 节点常驻、只换文字；拖选松手不关、遮罩上按下再松手才关；busy 时两次 Esc 都被拦下；迟到的 close 事件被忽略；`noValidate`。
  - 新增 `add-service-dialog.test.ts`，覆盖：共享 grid 布局；访问提示不在 alert 里；地址被拒后的焦点与 describedby；添加流程。
  - `glossary-page.test.ts` 补一条断言：判重被拒后焦点在原文框。
- **e2e**：
  - `ui.e2e.test.ts` 的风格页用例用 CDP 真实鼠标事件测三件事：拖选到遮罩上松手不关闭；在遮罩上点击会关闭；关闭后立刻重新打开，对话框不会自己合上。
  - 新增一条用例：把保存挂起，用真实点击按下「Save」，再连按两次 Esc（第二次之前把焦点移到页面本身），对话框都不关闭。
  - 三处反向验证：分别临时去掉 pointerdown 判断、keydown 拦截、迟到 close 判断，重新构建后对应用例都变红；还原后全绿。
  - 真机观察：单独运行时，焦点留在被禁用的「Save」上；但在完整 e2e 套件里，第二次 Esc 两次都关掉了对话框，说明焦点有时会离开对话框。
  - harness 的 `ExtPage` 新增 `input()`，可以向扩展页面发送原始输入事件。
- **视觉**：用新旧两个构建，在 zh_CN 和 en 下导出三个对话框内所有元素的位置、尺寸、字号和颜色逐项比对（临时脚本，不入库）。对话框尺寸与各元素的位置、尺寸都相同，差异只有标签结构（`label` 包裹改为 `div` + `label htmlFor`）和状态行里新增的零高包装节点。
- **完整检查**：`npm run check`、`npm run test:e2e`。
