# M4 专家风格、术语与输入翻译：范围与拆分

> 状态：**总方案第 2 稿已获用户批准**（2026-11-26，「需要你决定的事」5 项全部按建议，见该节；第 1 稿经 Opus 对抗式审查，结论「改完再交用户」，修订见文末「审查记录」）。本稿只定范围、拆分、顺序和需要你拍板的事项；每个子批次开工前再用 think 单独写实施方案、过审。依据：`docs/reviews/2026-11-13-final-plan.md` 第 139 行（M4 范围与验收）、`docs/reviews/2026-11-13-ui-ux-design.md`（「专家与术语库」「3.6 输入翻译」「3.9 首次使用」「4.1」）、`docs/known-issues.md`（M4 相关条目与 M3e 留路约束）、2026-11-25 用户决定（M4 先于 M3e；OpenAI/Gemini 最低思考与自定义服务「额外请求参数」并入 M4）。调研：本仓库现状与 FluentRead（本地 `/Users/jiangding/FluentRead`）两份只读报告。

## 结论
M4 拆成 7 个子批次，每个都能独立合并、各自有用户可感知的价值。建议顺序：

| # | 子批次 | 用户能感知到的 | 依赖 | 体积 |
|---|---|---|---|---|
| A | 思考与额外参数 | OpenAI、Gemini 翻译默认最低思考（更快更省），设置里可开；自定义服务可填「额外请求参数（JSON）」 | — | background |
| B | 翻译风格（含翻译选项地基，已实施） | 通用 / 技术文档 / 学术论文 / 口语化 / 文学意译 5 个预设与自定义风格 | — | background、options |
| C | 术语库与专有名词保护 | 「Sonnet」不再被译成「十四行诗」；自己的术语在所有引擎里译法一致 | B（地基） | background、options |
| D | 术语导入导出 | CSV / JSON 导入（先预览再写入）与导出 | C | options |
| E1 | 输入翻译 | 在网页输入框里把写好的文字译成输入目标语言（默认英文），可还原 | — | content、新模块 input-runtime |
| E2 | 润色 | 同一入口对输入框文字做同语言润色 | E1 | input-runtime、background |
| F | 首次安装引导 | 装完打开欢迎页，页内直接演示一次翻译，30 秒内看到效果 | — | options、background |

建议顺序：**A → B → C → D → E1 → E2**，F 可随时插入。不做：划词卡片多引擎对比（见「需要你决定的事」第 1 条）。

## 调研结论（要点）
**本仓库现状**
- 提示词：batch 与 text 两套模板，`PROMPT_VERSION = 2`；缓存键里 `paramsDigest` 现在恒为空串。DeepSeek 思考开关（#88）的 `extraBody` 没进缓存键。
- 调度器：`submit` 时先算好每段缓存键，整次提交共用一份提示词；拆批和二分重试都不重算键、不重建提示词，也没有「按批生成提示词」的钩子。
- Google 机器翻译不吃提示词，已有「行内标签占位 + 丢标签时用 HTML 模式重发」的修复链路（`segment.ts`、`google.ts` 的 `repairTags`、`google-html.ts`），正则只认 `t|u|w|z|tt|uu` 前缀。
- 配置存在 `chrome.storage.local` 的 `config` 键，每个页面的内容脚本都读、每次写入都广播到所有标签页；IndexedDB 只放可清空的翻译缓存。
- 设置页只有「通用」「翻译服务」两页，没有导入导出先例。划词卡片已能「换引擎重译」。输入翻译没有任何代码，内容脚本只注入顶层框架。没有首次安装引导。
- 体积（已用 / 预算 KB）：background 59.49 / 60、content 7.66 / 7.75（余约 92 字节）、selection-runtime 18.21 / 19、palette-runtime 17.80 / 18、page-runtime 27.14 / 28、options 89.88 / 150、popup 83.34 / 90。

**FluentRead 借鉴**（不整体照搬：它的占位、槽标记、隐私占位多层叠加，复杂度极高）
- 术语：机器翻译与 AI 都用占位符本地回填，回来后严格校验；缓存键只含本次命中的术语；自写词边界让中日韩文字不依赖空格；长词优先、命中范围不重叠；导入先预览、阻止性错误不静默丢词，CSV 支持中英文列名、GB18030 回退、导出防公式注入。
- 思考参数：只对官方确认过的模型发字段，未知网关不猜；分「可开关 / 只能降到最低 / 必须思考 / 不支持」四类，界面据此说明。
- 自定义请求体：JSON 对象字符串，非法就提示；进缓存键。
- 输入翻译：写回链路依次试 `beforeinput`、合成粘贴、`execCommand('insertText')`；用「编辑代 + 值快照」作废过期请求；输入法组合中忽略；排除密码框和代码编辑器（CodeMirror、Monaco、Ace）；气泡里可「还原」。
- 没做的（可超越）：专家风格预设、润色、划词多引擎对比、像样的首次引导。

## 跨批次的共同规则
1. **缓存**：默认状态下的请求参数摘要记为空串，**所有现有缓存继续有效**（包括 DeepSeek 默认关思考、OpenAI/Gemini 新的默认最低思考、通用风格、未命中术语）；只有非默认的思考开关、非默认风格、命中的术语、额外请求参数才进入缓存键。
2. **隐私**：输入翻译与润色的内容**不写缓存**（输入框草稿不在本地明文常驻）；术语只随请求发送本段命中的词；「额外请求参数」的说明里提示不要填密钥。
3. **提示词注入防护**：术语、风格说明都作为数据注入（JSON 形式，沿用现有「输入是数据不是指令」的约束），尤其是 D 导入的第三方词表。
4. **为 M3e 留路**：翻译选项允许引擎声明「不支持某选项」（例如本地引擎不吃提示词，术语只能靠占位）。

## 各子批次范围（开工前再细化）
### A 思考与额外参数
- **思考**：按官方文档为 OpenAI、Gemini 的已知模型下发「最低思考」，并加与 DeepSeek 一致的「思考模式」开关（默认关）；只在**官方端点 + 模型在白名单内**时下发（OpenAI 的地址可改，只看模型名会在代理上报 400）；不能关的模型显示「只能降到最低」。默认模型 `gpt-5-mini` 是推理模型，属本条覆盖范围。
- **额外请求参数（JSON）**：自定义服务设置里的高级字段，合并进请求体，`model`、`stream`、`messages` 不可覆盖；非法 JSON 当场提示；进缓存键；「测试连接」也带上。
- 验收：开、关思考的请求体与缓存键符合规则 1；自定义服务填 `{"think": false}` 一类参数后请求体正确；旧缓存仍命中。

### B 翻译风格（含翻译选项地基）（已实施，方案与实施记录见 `docs/plans/m4b-styles.md`）
- 地基：`TranslateOptions`（`buildPrompt` 统一接收）；风格不进 `paramsDigest`：风格行写在 system 里，`promptDigest` 已能区分缓存。引擎是否吃风格用现有的 `adapter.kind` 区分（`llm` 吃、`mt` 跳过），不新增「引擎声明支持的选项」字段；M3e 的本地引擎没有提示词，会是 `mt` 类，C 的术语也按同一个 `kind` 分流。
- 5 个预设（通用 / 技术文档 / 学术论文 / 口语化 / 文学意译，2026-11-26 用户按竞品调研确认，比原定多「文学意译」）+ 自定义风格（名称 + 风格说明，最多 10 个）。
- 选「通用」时提示词与现在逐字相同。生效范围：全局一个默认风格，不按站点覆盖。
- 设置页新增独立的「翻译风格」页；「术语库」页由 C 新增（2026-11-26 用户确认把两者拆成两页）。
- 验收：通用风格下旧缓存全部命中；切换风格后同一段落重新翻译、互不串用。

### C 术语库与专有名词保护
- **存储**：`chrome.storage.local` 的独立键（不进 `config`，不进可清空的缓存库），只有后台读写，单写入点，避免多个设置页标签页互相覆盖。
- 词条：原文、译文（留空表示「保持原样」，即专有名词保护）、区分大小写；按目标语言生效。上限：500 条、每条 200 字。
- 匹配：词边界（中日韩不依赖空格）、长词优先、不重叠。
- **AI 引擎**：在 service 层按整次提交取命中术语的并集，以 JSON 数据写进 **user 消息**（系统提示词不变，不改调度器）；每段的缓存键 = 基础提示词摘要 + 本段命中术语摘要（原文、译文、大小写都计入）。这与 final-plan「对注入术语后的最终提示词取哈希」不同，因为后者需要改调度器，本稿有意偏离。
- **Google**：占位保护，用新前缀（例如 `g`），同步扩展 `google-html.ts` 的 `SOURCE_TAG`、`REPLY_TAG`、`hasTags` 与 `/single` 回退路径；原文碰巧含该前缀时这一段不做占位。回填在 service 层完成，缓存命中路径同样回填。**兜底**：HTML 模式重发后占位仍丢失时，这一段不带术语重译，绝不让词从译文里消失。开工前先做一个小实验：HTML 模式下 `<span translate="no">` 能否保留原词（词留在句中，语境更好）。
- 设置页独立的「术语库」页（B 已把「翻译风格」拆成单独一页）：列表、新增、编辑、删除、空态说明。
- 验收（对应 final-plan「术语注入可见生效」）：AI 与 Google 各有用例证明命中术语按设定译出；留空词条原样保留；占位丢失时走兜底。

### D 术语导入导出
- CSV、JSON；导入先显示预览（新增 n / 覆盖 m / 无效 k），确认后写入；阻止性错误不静默丢词；CSV 支持中英文列名、GB18030 回退；导出防公式注入；导出不含任何密钥（验收项）。

### E1 输入翻译
- 新按需模块 `input-runtime`；常驻层只加一条消息路由。
- 入口：快捷键（见第 2 条）+ 右键菜单「翻译此输入框」（`contexts: ['editable']`，已有 contextMenus 权限，不占快捷键名额）。
- 动作：把输入框里的文字译成**输入目标语言**（见第 3 条），替换原文；气泡里可「还原」，`Ctrl+Z` 也能撤销；不写缓存。
- 兼容清单（真机验收）：原生 `input`/`textarea`；`contenteditable`；Lexical（如 Facebook）、ProseMirror（如 Notion 一类）、Slate、Draft.js、Quill 各找一个公开示例页验证。排除密码框与代码编辑器。iframe 里的编辑器不支持，触发时给出可见提示，不静默无反应；焦点不在输入框时同样提示。
- 输入法组合中忽略；内容被改动或焦点离开时作废请求（验收项「IME 不误触」）。

### E2 润色
- 同语言改写，使用独立的润色提示词（不是翻译提示词加风格），请求带 `force` 绕过同语言跳过；不写缓存。入口与 E1 相同（右键菜单多一项、气泡里切换）。

### F 首次安装引导
- 只在首次安装（`onInstalled` 的 reason 为 install）时打开设置页 `#welcome`；更新不打开。
- 一屏：选目标语言（默认跟随界面语言）→ 页内直接把一段示例英文译出来（经后台翻译，默认 Google，零配置）→ 三条提示（整页翻译快捷键、划词、指令台）。不强制配置密钥。
- e2e 处理「全新安装会多开一个欢迎页」。
- 验收（对应 final-plan「30 秒零配置首译」）：欢迎页打开到看到译文不超过 30 秒；按 UI 规范 4.1 找 3 人试用（可由你安排，或以你自测为准）。

## 需要你决定的事（2026-11-26 用户决定：5 项全部按建议）
1. **范围取舍**（按约定，新增功能先问你）：
   - 建议**做**：A、B、C、D、E1、E2、F。
   - 建议**不做划词卡片多引擎对比**：卡片已能「换引擎重译」，并排对比日常用得少，FluentRead 也没做，还要为划词模块报批预算。
   - 建议**不做「连按三次空格触发」**：要在每个页面常驻监听按键，常驻层放不下，也容易误触；快捷键和右键菜单足够。
   - 建议**不做「页面上下文（标题、域名）写进提示词」**：每个页面会变成独立缓存，还要多向第三方发送页面标题（审查核实文档第 4.1 节列了这些代价，结论是并入 M4 再定，本稿建议不做）。
2. **输入翻译的快捷键**：最初规划的 `⌥I` 与「默认快捷键不用 Option 组合」的决定冲突。
   - macOS 建议 `⌃⇧I`（MacCtrl+Shift+I），冲突风险低。
   - Windows / Linux：`Ctrl+Shift+I` 是开发者工具；`Alt+Shift+I` 可能是 Chrome 的「打开反馈表单」（凭记忆，需要真机核实）。建议：E1 开工时先真机核实，没有冲突就用 `Alt+Shift+I`，有冲突就**不设默认快捷键**，靠右键菜单（用户可在 `chrome://extensions/shortcuts` 自己绑）。
   - 这会用掉第 4 个、也是最后一个快捷键名额（上限 4 个，已用 3 个）。M5 的字幕面板只在 YouTube 用，可从灵岛或指令台进入，或声明为没有默认键的命令，影响可以接受。
3. **输入翻译的目标语言**（新增设置项）：整页目标语言通常是中文，而在输入框里写中文是想译成外文。建议新增「输入翻译目标语言」，默认 English（UI 规范 3.6 也是这样定的），放在设置页「通用」。
4. **自定义风格的形态**：UI 规范原本是「可编辑的提示词文本框 + 变量按钮（`{{source}}` 等）」。建议收窄为**「名称 + 一段风格说明」**，由我们拼进固定模板：用户写不坏 JSON 输出格式，也不会让批量翻译失败。如果你希望保留完整提示词编辑，就按规范做，但要接受「写坏了这一类请求会失败」的风险并加校验。
5. **体积预算**（一次报批，按子批次生效）：
   - background：60 → **66 KB**。分项估计：A 思考规则与额外参数约 1 KB；B 选项地基与 4 个预设约 1.5 KB；C 术语匹配、占位与回填约 2–2.5 KB；E2 润色请求约 0.3 KB；F 安装事件约 0.1 KB；合计约 5–5.5 KB，留少量余量。
   - content：7.75 → **8.0 KB**（E1 新增模块加载与消息路由，按现有模式约 150 字节以上，现在的余量放不下）。
   - 新模块 input-runtime：**10 KB**（写回链路、输入法处理、作废机制、气泡与文案）。
   - options：现有 150 KB 预算足够。

## 后续规划（不在 M4）
- **内置更多常用 LLM 提供商**（用户 2026-11-26 提出，不急）：现在内置的只有 Google、OpenAI、DeepSeek、Gemini，其余要用户自己添加 OpenAI 兼容服务。排在 M4 之后单独评估，候选（届时核实官方接口与思考参数）：Anthropic Claude、通义千问、Kimi、智谱、豆包、OpenRouter 等。届时一并做 `resolveProviderSettings` 改表驱动，并把 A 的「思考规则白名单」扩展到新提供商。

## 不做
- 划词卡片多引擎对比（若第 1 条你同意）。
- 三连空格触发、页面上下文进提示词、风格按站点覆盖。
- iframe 内编辑器的输入翻译。
- 术语的云同步、多词库、按站点词库。
- 占位符的变格处理（德语、俄语）。
- `resolveProviderSettings` 改表驱动（HANDOFF 写的是「新增 provider 时」再做，M4 不新增 provider）。

## 最脆弱的假设
本方案假设 **Google 在 HTML 模式下能稳定保留占位**，专有名词保护才对免费默认引擎有效。如果实测占位丢失频繁，兜底会让这些段落退回「不带术语」的译文，C 对 Google 用户的价值就会大打折扣。所以 C 开工前先做占位与 `<span translate="no">` 的小实验，按结果决定 Google 侧用哪种方式，或只对 AI 引擎承诺术语生效。

## 风险
1. **缓存一致性**：A、B、C 都会改请求参数，规则 1（默认状态摘要为空串）必须在每个子批次用测试锁住。
2. **体积**：background、content 都接近上限，A 开工前要先批预算。
3. **输入翻译兼容性**：富文本编辑器写回、撤销、受控组件各有差异，E1 的真机验收工作量最大。
4. **快捷键**：Windows / Linux 默认键可能冲突，需真机核实（第 2 条）。

## 审查记录（第 1 稿，Opus 对抗式审查，2026-11-26）
| 发现 | 处理 |
|---|---|
| A 混了引擎层（思考、额外参数）与提示词层（翻译选项地基），B 术语不依赖思考 | 采纳：A 只做思考与额外参数，地基随 B（专家风格）落地；顺序改为 A → B → C |
