## 设计
- **原型**：Design 画布「M4 翻译风格与术语库」页的 `GlossaryTransferM4D` 画板（https://claude.ai/artifact/GJTgsP7SFHmhP6M2SczwTp#artboard-GlossaryTransferM4D），右侧便签说明交互。
- **复用的现有部件**：
  - 分区标题行与圆角按钮（`.addButton`）；
  - 卡片列表（subgrid）；
  - 640px 对话框，即「对话框统一」会话产出的 `DialogShell`；
  - 下拉层：导出菜单、编码切换；
  - 页头的「已保存」提示 `notice`：导入成功和导出完成时用它提示。
- **要点**：
  - **标题行**：右侧依次是「导入」「导出 ▾」「添加术语」。
    - 导出菜单有两项：CSV（可用表格软件编辑）、JSON（适合备份或换设备导入）。
    - 没有术语时，「导出」禁用。
    - 词库由更新版本的扩展写入时（只读），「导入」「导出」都禁用，并说明原因。
  - **筛选框**：有术语时出现在列表上方，按原文或译文过滤，不区分大小写；没有匹配时，卡片里显示一行说明；导入成功后自动清空。
  - **导入对话框**分两步：
    1. **选择**：拖放文件，或点按钮选文件；下方附格式说明。
    2. **预览**：
       - 显示文件名、行数、编码；编码是回退猜出来的时候，可以手动切换；
       - 第 1 行被当成表头时，明确提示；
       - 新增、覆盖、不变、无效四个计数；
       - 逐行显示状态，覆盖的行显示「旧 → 新」；
       - 无效行列出行号（JSON 为条号）和原因；
       - 主按钮写明要导入的条数；有阻止性错误时禁用，并用红色横幅说明原因和怎么处理。

## 方案

### 1. 解析与预览（新文件 `src/lib/glossary/transfer.ts`，纯函数，只在设置页使用）
- **读取**：
  - 一次拖入多个文件或文件夹：提示「一次只能导入一个文件」。
  - 文件超过 1 MB：不读取，直接报阻止性错误。
  - 以 `PK\x03\x04` 开头（xlsx）：提示「不支持 Excel 文件，请另存为 CSV」。
  - 编码按以下顺序判断：
    1. 以 `FF FE` 或 `FE FF` 开头：按 UTF-16LE 或 UTF-16BE 解码（fatal）。
    2. 前 1 KB 里有 NUL 字节：按 NUL 落在偶数位还是奇数位，判断为无 BOM 的 UTF-16LE 或 BE（fatal）。
    3. 其余：按 UTF-8 解码（fatal），去掉 BOM。
    4. UTF-8 失败且没有 UTF-8 BOM：按界面语言回退，繁体界面用 Big5，其余用 GB18030。
    5. 仍然失败：报「无法读取这个文件」。
  - 走了第 4 步的文件，预览里可以手动把编码切换为 GB18030、Big5 或 Shift_JIS，切换后重新解析。
  - 超过 2000 行：报阻止性错误。新增的有效行最多只能有 500 条，没必要全量解析几万行。
- **识别格式**（看内容，不看扩展名）：
  - 去掉开头空白后，首字符是 `{` 或 `[`：先尝试 `JSON.parse`。
    - 解析失败：回退按分隔文本处理（`[GPT]` 这样开头的 CSV 很常见）。
    - 解析成功但结构认不出：报「JSON 格式不正确」。
  - 分隔文本：第一个非空行里，只要引号外出现 Tab，就按 TSV 解析，否则按 CSV。
- **CSV / TSV 解析**：
  - 手写 RFC 4180 状态机，`""` 表示一个双引号。
  - 引号里的换行替换成一个空格，行号仍照常累计。
  - 全部字段都为空的行直接跳过，例如 Excel 导出的 `,,,`。
  - 引号不完整：报阻止性错误「CSV 第 N 行引号不完整」。
- **表头**：
  - 列名先转小写，再去掉空格、`_`、`-`，然后按下面的别名识别：
    - 原文：source、sourceterm、term、原文、原词、术语；
    - 译文：target、targetterm、translation、译文、译词、翻译；
    - 目标语言：lang、language、targetlanguage、tgtlng、目标语言、语言；
    - 区分大小写：casesensitive、matchcase、区分大小写、大小写敏感。
  - 第一行同时有原文列和译文列，才当作表头，并在预览里提示「第 1 行作为表头」。
  - 认不出的列：提示「忽略了未识别的列：X」。
  - 同一列出现两次：报阻止性错误。
  - **没有表头时**：
    - 前两列当作原文和译文；
    - 第 3 列的所有非空值都能识别成语言时，当作目标语言列；
    - 第 4 列的所有非空值都能识别成布尔值时，当作区分大小写列；
    - 不能识别的列，提示「忽略了第 N 列」。
- **JSON**，接受两种结构：
  - 本扩展导出的 `{"format":"islet-translate.glossary","version":1,"entries":[…]}`。`version` 大于 1 时，提示「这个文件由更新版本的扩展导出，请先升级扩展」。
  - 条目数组 `[{source,target,lang?,caseSensitive?}]`，键名按上面的别名识别。
  - 无效条目的原因写「第 N 条」。
- **字段取值**：
  - 原文、译文：去掉控制字符和首尾空白。不做 NFC 规范化，与现有的添加对话框和后台 `cleanDraft` 保持一致（见 m4c 已知限制）。
  - 反公式转义：单元格以 `'` 开头、且下一个字符是 `= + - @`、Tab、CR、LF 之一时，去掉这个 `'`。
  - 目标语言：先用 `normalizeLanguage` 识别，再认 `LANGUAGES` 里的自称名称。
    - 译文为空：忽略目标语言，对所有语言生效。
    - 译文不为空、目标语言为空：取当前目标语言。
  - 区分大小写：认 true / false / 1 / 0 / yes / no / 是 / 否，不区分大小写；空值按「否」。
- **单行校验**：下列情况判为无效，并给出行号（或条号）和原因：
  - 原文为空；
  - 原文或译文超过 200 字；
  - 目标语言不支持；
  - 区分大小写的值认不出；
  - 比表头多出了非空的列。尾部缺列不算错，按空值处理。
- **重复与比较**（按 `source.toLowerCase()` 建 Map 分桶，只在同一个桶里调用 `isDuplicateEntry`，整体复杂度 O(n)）：
  - **文件内重复**：只在有效行之间比较。与前面某个有效行重复的，判为无效，原因是「与第 N 行重复」。
  - **与已有术语比较**：
    - 没有重复：**新增**。
    - 只与一条已有术语重复：
      - 原文、译文、目标语言、区分大小写四项完全相同：**不变**；
      - 否则：**覆盖**，并记下是哪一行认领了这条已有术语。同一条已有术语被第二行认领时，第二行判为无效，原因是「与第 N 行覆盖的是同一条术语」。
    - 与多条已有术语重复：判为无效，原因是「与已有的多条术语重复」。
- **阻止性错误**（整份都不能导入）：
  - 文件超过 1 MB 或超过 2000 行；
  - 无法读取，或是 xlsx；
  - 引号不完整；
  - JSON 格式不正确，或由更新版本导出；
  - 表头有重复的列；
  - 没有任何有效行；
  - 已有条数加上新增条数超过 500。
- **全部「不变」时**：不算阻止性错误。提示「术语库已包含文件里的全部术语」，主按钮禁用。
- **其他情况**：无效行在预览里逐条列出，主按钮写明只导入几条，用户明确确认后才写入。
- **预览上限**：逐行列表最多显示 200 行，无效原因最多列出 50 条，超出部分分别显示「还有 n 行未显示」「等 n 处」。计数始终按全量统计。

### 2. 写入（后台一次完成，带基线比对）
- `GlossaryChange` 新增一种：`{ type: 'import', base: string, entries: ImportEntry[] }`。
  - `entries` 是写入后的**完整列表**，顺序就是显示顺序。已有条目带 `id`，新条目不带。
  - `base` 是设置页预览时，用当时的词库生成的标准化字符串：按顺序对每条的 id 和四个字段做 `JSON.stringify`。
- 后台在队列里、写入之前按顺序处理：
  1. 用当前词库按同样的规则算出字符串，与 `base` 比较；不一致就报 `config/glossary-stale`，一条都不写。这样能覆盖所有并发情况：别处删除、修改、新增，以及「不变」行对应的条目在别处被删。
  2. 按写入后的最终状态校验：每个带 `id` 的条目都存在，且 id 不重复；字段合法；任意两条都不重复；总数不超过 500。
  3. 带 `id` 的条目用 `{...existing, ...draft}` 合并，保留未知字段；新条目逐个生成 id，并逐个加入已占用集合。
- 设置页的处理：
  - 收到 stale：用最新词库自动重新预览，并提示「术语库刚被修改过，已按最新内容重新预览」。这条提示由设置页自己处理，不加进 `error-messages` 表，省 background 体积。
  - 对话框打开期间，`watchGlossary` 收到变化时，同样自动重新预览。
- 不新增目标语言，`glossary` 的 version 不变。

### 3. 导出（设置页，纯前端）
- 只显式取四个字段：原文、译文、目标语言、区分大小写，不展开条目对象。因此不含 id、未知字段、配置或任何密钥。
- **CSV**：
  - UTF-8 BOM，CRLF 换行，所有字段都加双引号，`"` 写成 `""`；
  - 表头 `source,target,lang,caseSensitive`；
  - 防公式注入：以 `= + - @`、Tab、CR、LF 开头的单元格，前面加 `'`，导入时按第 1 节的规则还原。
- **JSON**：`{"format":"islet-translate.glossary","version":1,"entries":[…]}`，缩进 2。
- **文件名**：`islet-glossary-YYYY-MM-DD.csv` 或 `.json`。
- **下载**：用 Blob、`URL.createObjectURL` 和 `a[download]` 触发；`revokeObjectURL` 放在 `setTimeout` 里调用。
- 导出后，页头提示「已导出」（复用 `notice`）。

### 4. 设置页
- **`GlossaryPage.tsx`**：
  - 「导入」按钮，以及「导出」菜单 `ExportMenu`：`role=menu`，Esc 和点外部都能关闭，方向键可以移动。
  - 筛选框。
  - 导入成功后：
    - 用 `notice` 提示「已导入 n 条（新增 a，覆盖 b）」；
    - 清空筛选；
    - 新增和覆盖的行一起闪一下（`flash` 改成 Set）；
    - 焦点回到「导入」按钮。
  - 只读时禁用「导入」「导出」。`src/lib/glossary/client.ts` 需要多返回一个 `readOnly`。
- **`GlossaryImportDialog.tsx`**：
  - 用 `DialogShell`，分「选择」「预览」两步。
  - 隐藏的 `<input type="file" accept=".csv,.tsv,.txt,.json">`，配一个看得见的按钮；整个虚线区域都能拖放。
  - 对话框打开期间，在 window 上拦截 `dragover`、`drop`（`preventDefault`），文件拖到区域外也不会让标签页直接打开它。
  - 读取和解析期间显示「正在读取…」。
  - 「重新选择」回到第一步。
  - 写入失败（写入失败、只读、超出上限）的提示，显示在对话框底部的错误行。

### 7. 体积
- options（95.31 / 150 KB）：解析、导出加两个新组件，估计 +6–8 KB。
- background（65.14 / 66 KB）：**超出已批预算的增量**。m4.md 的预算分项里没有 D。import change、base 比对和最终状态校验估计 +0.3–0.5 KB，增加后为 65.45–65.65 KB，剩 0.35–0.55 KB，E2 约 0.3、F 约 0.1 勉强放得下。
  - 实施时先做 PoC 实测。实测超过 0.5 KB，或之后 E2、F 放不下时，再请你批准把预算提到 67 KB。
- content：不变。

## 已定取舍（用户 2026-11-26 同意按建议处理）
1. **编码回退**：繁体界面回退 Big5，其余回退 GB18030；预览里可以手动切换为 GB18030、Big5、Shift_JIS。这一条对 m4.md 只写「GB18030 回退」做了扩展。原因：台湾、香港的 Windows Excel 存 CSV 默认是 Big5，只按 GB18030 回退，会把这类文件静默解成看起来正常的乱码。
2. **background 体积**：这次不调整预算，只登记为超出已批预算的增量，按第 7 节处理。
3. **砍掉粘贴导入**：m4.md 没有要求，砍掉后界面、文案和测试都更简单。从表格里复制的内容，可以先另存为 CSV 再导入。

## 不做
- 粘贴导入，见上一节第 3 条。
- 多词库、按站点词库、内置词表、云同步，m4.md 已定不做。
- 导出时选择导出哪些条目，或只导出筛选后的结果。
- 冲突策略选项（例如「跳过已有」）：统一以文件为准覆盖。
- Anki 格式、生词本，留到 M5。

## 测试
- **transfer 单元测试**：
  - 编码：
    - UTF-8 带 BOM、不带 BOM；
    - UTF-16LE / BE 带 BOM，以及无 BOM 靠 NUL 识别；
    - 回退 GB18030；繁体界面回退 Big5；手动切换到 Shift_JIS；
    - xlsx；无法读取。
  - 格式：
    - JSON、CSV、TSV；
    - 以 `[GPT]` 开头的 CSV 能回退按分隔文本处理；
    - 「`Hello, world⇥你好`」判为 TSV。
  - CSV 状态机：引号、`""`、引号内换行变空格且行号正确、全空行跳过、引号不完整。
  - 表头：
    - 中英文别名、大小写与连字符；
    - 没有表头时取前两列，第 3、4 列能识别就用上，不能识别就提示；
    - 认不出的列；重复的列。
  - 字段：
    - 反公式转义；
    - 语言代码、别名和自称名称；
    - 译文为空时忽略语言；
    - 区分大小写的各种取值；
    - 尾部缺列；多出非空列。
  - 统计：
    - 新增、覆盖、不变（含「只有原文大小写不同」应算覆盖）、无效（每种原因各一例）；
    - 文件内重复只看有效行；
    - 两行认领同一条已有术语；

## 最脆弱的假设
**设置页里同步解析加预览足够快。** 有 2000 行上限，分桶后复杂度是 O(n)，预览只渲染 200 行，预计远低于 50 ms，单元测试会实测。如果做不到，先降低行数上限，不引入 Worker。

## 已知限制（写进 known-issues）
- Excel 会把 `1-2`、`MARCH1`、`007`、`TRUE` 这类内容改成日期或数字，存回去再导入，会被当成新词。
- Mac 版 Excel 的普通「CSV」格式会丢中文，要用「CSV UTF-8」或 JSON。
- 原文本身以「`'` + `= + - @`」开头的词，导出后再导入会少一个 `'`。
- 同时拖入两个以上的文件时，只提示，不做批量导入。

### 与方案的偏差
1. **繁体列名**：表头别名在方案列出的简体之外加了繁体写法（原詞、術語、譯文、譯詞、翻譯、目標語言、語言、區分大小寫、大小寫敏感）。原因：繁体界面的格式说明按简体意思翻译后写的是「譯文」「目標語言」，不认繁体就与说明自相矛盾；Big5 回退也是为繁体用户。
2. **反公式转义只用于 CSV / TSV**：JSON 导出不加 `'`，所以 JSON 导入也不去 `'`，JSON 往返无损（known-issues 第 8 节第 3 条注明）。
3. **回退编码也解不开时仍显示编码切换**：方案第 5 步只说报「无法读取」；实现保留阻止性横幅，同时让用户可以改选 Big5 / Shift_JIS 再试，不新增文案。
4. **`DialogShell` 加两个可选属性**：`submitLabel` 可省略（「选择」步只有「取消」）、`onCancel` 可替换取消按钮的动作（「预览」步为「重新选择」），按原型的页脚；现有三个对话框不受影响。
5. **预览里原文为空的行显示「—」**：原型写「（空）」，但第 5 节没有这条文案，不新增；原因在下方无效列表里写明。
6. **JSON 的计数也写「行」**：文案「$1 · $2 行 · $3」只有一种，JSON 时 $2 为条目数；无效原因里「与第 $1 行重复」在 JSON 下同样写「行」（第 5 节只给了这一种）。
7. **只读时除了按钮 `title`，列表下方也显示一行原因**（复用现有文案），与「已达 500 条」的提示同样位置。
8. **e2e 的 deny 设在 harness 全局**，而不是只在导出用例里设：所有 e2e 都不该写下载目录。

### 实现审查（check skill，Opus，2026-11-26）
结论：没有必须修改的问题；3 条建议与 2 条可忽略项都已修，并补回归用例（对话框两条在修复前的代码上确认会失败）：
1. **TSV 嗅探与读取器的引号规则不一致**：嗅探把任何 `"` 都当成引号开关，无表头 TSV 的第一行出现 `12" pizza` 这类落单引号时会误判为 CSV，整行并成一格。改为与读取器相同：只有单元格开头的 `"` 才开引号，`""` 视为转义。
2. **预览步关闭后重开，初始焦点落空**：`step` 仍是 `preview`，「选择文件」按钮尚未渲染。`onOpen` 里预先设 `focusNext = 'choose'`，换步后由已有 effect 聚焦。
3. **对话框关闭后仍响应存储变化**：导入成功后存储变化晚于响应到达时，淡出中的对话框会对自己的写入闪出「术语库刚被修改过」，之后在设置页增删术语也会在关着的对话框里重算预览。改为关闭时忽略，下次打开时重新读取。
4. **后台导入不删词**（可忽略项，顺手加固）：导入列表必须包含全部已有条目，漏掉的一律 `config/glossary-invalid`。
5. **「已包含全部术语」只在没有无效行时出现**（可忽略项）：有无效行、无新增覆盖时不再显示这条提示，主按钮照旧禁用。
