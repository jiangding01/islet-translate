# 界面方向：隐中生岛

> 状态：**方向已确认**（2026-11-14，用户确认），细节待各批次实现时落地 · 取代 `docs/reviews/2026-11-13-ui-ux-design.md` 中「悬浮球常驻、本站隐藏」的设计（3.3 节），以及 3.1 节弹窗的信息结构；其余 token、页内译文样式、可访问性和性能预算仍然有效
> 原型：https://claude.ai/artifact/GJTgsP7SFHmhP6M2SczwTp 「隐中生岛 · 推荐」页
> 最高原则：人的感受第一。少打扰；译文就像网页本来的样子；近乎原生的沉浸式阅读。

## 1. 核心模型：同一个对象的三层

| 层 | 形态 | 何时出现 |
| --- | --- | --- |
| 0 · 隐 | 页面上零痕迹 | 默认状态。母语页面和用户没有唤起翻译的页面，永远停在这一层 |
| 1 · 岛 | 贴边的小点，鼠标靠近时生长成竖排灵岛：双 / 译 / 原、重试、引擎、⌘ | 用户唤起翻译后（工具栏图标、`⌃⇧A`、右键菜单），或者站点规则是「总是翻译此站」 |
| 2 · 台 | 灵岛作为铰链，指令台像抽屉一样从它朝页面内侧拉出 | 点灵岛上的 ⌘，或按指令台快捷键 |

**所有操作都是指令**：灵岛按钮、指令台、快捷键和右键菜单，调用的都是同一张指令注册表，比如 `page.translate`、`view.translationOnly`、`engine.switch`、`retry.failed`、`vocab.add`。新增一种入口只是换一个外壳，不需要改动内核。

**不做多套 UI 皮肤**：可以自定义的只有第 3 节列出的少量偏好。

## 2. 体验审查：必须处理的问题

1. **右侧小点和滚动条冲突**：右边缘正是滚动条的位置，用户拖滚动条时很容易误触，把灵岛撑开。处理方式：
   - 小点离开视口边缘 16px，不压在滚动条上；
   - 用**悬停意图**判断要不要展开：鼠标停留超过 120ms，且移动速度低于阈值才展开；
   - 鼠标按下拖动时、滚动时，不触发展开；
   - 放在左侧时没有这个问题。
2. **快捷键冲突**：`⌘K` 已经被 GitHub、Slack、Notion、Linear 等大量网站占用，不能抢。指令台改用 Chrome commands 注册 `⌃⇧K`，用户可以在 `chrome://extensions/shortcuts` 里修改。界面上显示的永远是**实际生效的快捷键**，不写死 ⌘K。
3. **整页进度没有总数**：懒翻译是滚到哪翻到哪，「18/43」这种总数是假的。进度只表达「视口内是否还有段落在翻译」：小点上有一圈细弧表示正在翻译视口内容；整页模式才显示计数。
4. **与网站自己的浮动元素重叠**：客服气泡、回到顶部按钮、Cookie 横幅常常也在右下角。贴边位置要做碰撞检测：在预设高度上发现有固定定位的元素时，自动沿边缘避让。用户也可以沿边缘拖动小点，位置按站点记住。
5. **没有悬停能力的设备**：触屏或手写笔下没有 hover，点击小点同样会展开，点灵岛外部则收起。
6. **全屏和打印**：视频全屏、`<dialog>` 打开、打印时，小点和灵岛全部隐藏。
7. **颜色要和宿主页反差**：灵岛在任何网页上都是同一个深色物体。亮色网页上用石墨深色；暗色网页上用「深岛 + 细描边」，深岛比宿主背景亮一档，外加一圈 1px 浅描边，不改用浅色（见第 6 节，2026-11-14 确认；2026-11-16 原型 `IsleM2` 复核后保持）。区分亮暗的依据是宿主背景亮度，不是系统主题。这样在任何网页上都能看清，又不像贴上去的广告。
8. **iframe**：灵岛只在顶层 frame 出现；子 frame 的翻译进度汇总到顶层。
9. **「原」的语义**：点「原」表示结束本次翻译。页面恢复原样，灵岛退场，但缓存保留，再按一次 `⌃⇧A` 可以瞬间恢复译文。单段切换原文用段落左侧的「原」按钮，不影响整页。
10. **键盘与读屏**：不往网页的 Tab 顺序里插焦点。键盘用户通过快捷键唤起；灵岛展开后，焦点进入灵岛内部，`Esc` 退出并把焦点还给原来的位置。进度用 `aria-live="polite"` 播报，只在开始和完成时各播报一次。

## 3. 位置配置

- 可选的停靠位置：**右侧（默认）/ 左侧 / 底部**，在设置里选，也可以用指令台的「停靠到左侧」。
- 几何形状按「贴边坐标」定义，即沿边长度乘以离边深度，同一套实现适配三种位置：
  - 左、右侧：竖排灵岛，指令台朝页面内侧（另一侧）拉出；
  - 底部：横排灵岛，落在右下角（不居中，避开正文阅读列），向左生长，指令台向上拉出；遇到贴底的通栏横幅时抬到横幅上方。
- 沿边缘的位置可以拖动，按站点记住；全局默认停在中间偏下（右侧 60% 高度处）。
- 其余可配置项只有两个：译文样式（4 种），以及「外语页面显示小点」（默认关闭，开启后在外语页面上提前显示零层的小点）。

## 4. 加分点

1. **磁吸生长**：小点会随鼠标的**距离**连续变大，而不是悬停到一定时间后才突然展开。手越靠近，小点越大，达到阈值时长成灵岛。这是用户说的「逐渐显示」最自然的实现，也是这套方案的标志性手感，类似 macOS Dock 的放大效果，但只有一个对象。
2. **阅读位置锚定**：切换「双 / 译 / 原」时，以视口中心那一段作为锚点，切换后滚动位置保持不动，正在读的那一行不会跳走。沉浸感能不能保住，关键就在这里，**必须做**。
3. **指令台兼作快速翻译框**：输入框里写的不是指令，就直接翻译这段文字，结果显示在列表上方；以 `/` 开头才强制当作指令。这样一个入口同时满足「找功能」和「临时翻一句」。
4. **按情境排序的指令**：有失败段落时「重试」排第一；刚划过词时「收入生词本」排第一。指令台不仅响应用户，也知道当前状态。
5. **按住修饰键偷看原文**：按住 `⌥` 不放，整页临时显示原文，松开立刻恢复，没有任何 UI。适合想快速核对原文的人。
6. **段落级「原」按钮也用生长动效**：从段落左侧的一个小点长出来，和灵岛共用同一套动效语言，整个产品只有一种动起来的方式。

## 5. 动效规范：丝滑、浑然天成

**原则**：只有一个物体在生长；任何时刻都可以打断；打断时从当前位置平滑转向，不跳帧、不回到原点重来。

1. **单一形状**：小点、灵岛、指令台是**同一个 DOM 元素**。外形由贴边坐标的四个量决定：沿边长度、离边深度、圆角、沿边偏移。不同状态只是改变这四个目标值，不切换元素。
2. **弹簧驱动，不用固定时长**：几何量用临界阻尼附近的弹簧插值，生长时有约 2% 的轻微过冲，显得有生命感，收缩时不过冲。参考值：
   - 生长：stiffness 380、damping 30，约 280ms 到位；
   - 收缩：stiffness 520、damping 42，约 200ms；
   - 指令台展开：stiffness 300、damping 30，约 340ms。
   
   弹簧在被打断时保留当前速度，直接朝新目标转向，这是「无缝」的关键。固定时长的 CSS transition 做不到。
3. **渲染路径**：外形用 `clip-path: inset(... round r)` 绘制，每帧由 rAF 驱动的弹簧求值，只写这一个属性，绝不触发布局。阴影放在一个跟随的独立层上，避免 `filter` 和 `clip-path` 一起重绘。实现时必须在 4 倍 CPU 降速下测到 60fps，掉帧时改为 transform 方案（外层 `scale` 加内层反向 `scale`，圆角用 SVG 绘制）。
4. **内容编排**：
   - 旧状态的内容在形变的前 35% 内淡出，同时轻微朝边缘位移 4px；
   - 新状态的内容在后 60% 内淡入；
   - 内容锚定在贴边一侧，不随形状中心漂移，所以生长时看起来是从边缘长出来的，而不是放大。
5. **选中指示器共享**：「双 / 译 / 原」的选中背景是一个独立的块，切换时用弹簧沿轴滑动到新位置，不在旧按钮上消失、在新按钮上出现。
6. **译文的出现与消失**（用户要求「丝滑出现、自然消失」，同时权衡成本和性能）：
   - **懒加载是前提**：视口内的段落优先翻译，IntersectionObserver 的 `rootMargin` 为 1000px，提前预取即将滚入视口的段落（M2 必做）。视口外的段落在用户看到之前就已经静默插入，**不需要动效**；只有视口内的段落播放动效。
   - **出现**：分两级，按设备性能自动选择：
     1. **基础级（默认，几乎零成本）**：只用 `opacity` 0→1 加 `filter: blur(2px)`→0，200ms，同一批内各段错开 30ms，最多错开 6 段，超过 6 段的同时出现。这两个属性都交给合成器处理，不触发布局计算。插入时依靠浏览器原生滚动锚定，没有手动锚定。实测（2026-11-18，见 `paragraph-loading.md`）：视口上方插入完全补偿，视口内插入只保住视口顶部那段，下方的段落会被推下。
     2. **增强级（可选）**：视口内的段落额外做**高度展开**：用 `interpolate-size: allow-keywords`，Chrome 129 起支持，从 `height: 0` 过渡到 `auto`，下方内容随之平滑下移，不会突然被挤开。这一级会逐帧触发布局计算，所以**只对视口内最多 8 段生效**；某一帧耗时超过 8ms，就自动降级到基础级。实现时用 4 倍 CPU 降速实测，决定是否默认开启。
   - **消失（结束翻译或切回原文）**：视口内的译文先做 `opacity` 1→0 加轻微 blur，140ms；淡出结束后，在同一帧里一次性移除全部译文节点，避免逐段移除时页面反复重排。移除前后做阅读位置锚定，保证原文那一行不动。视口外的译文直接移除。增强级下，视口内段落的高度收拢到 0，再移除。
   - **双语与只看译文的切换**：先锚定阅读位置，再做 120ms 的交叉淡化。页面上的任何文字都不做位移动画。
   - **减少动态效果**：开启 `prefers-reduced-motion` 时，出现和消失都直接完成，不做模糊和高度过渡。
7. **减少动态效果**：开启 `prefers-reduced-motion` 时，形变直接到位，只保留不超过 120ms 的透明度变化。
8. **性能预算**：灵岛和指令台挂在一个 Shadow DOM 宿主下，宿主样式为 `contain: layout paint style`；只在动画期间设置 `will-change`；动画期间不读取布局，碰撞检测在动画开始前做完。

## 6. 主题色：琥珀（2026-11-14 用户确认）

取代 M0 的「墨青」。强调色只用在很小的面积上：小点、进度、选中、⌘ 高亮、工具栏图标着色、主按钮。正文、表面和边框都是带一点暖调的中性色（色相 70–80，色度 ≤ 0.012），和琥珀属于同一个色温。

| token | 亮色 | 暗色 | 用途 |
| --- | --- | --- | --- |
| `accent` | `oklch(0.81 0.15 76)` | `oklch(0.82 0.15 78)` | 填充：小点、进度、主按钮、开关；深色表面上的 ⌘ 高亮 |
| `accent-ink` | `oklch(0.52 0.12 60)` | `oklch(0.84 0.14 78)` | 浅色背景上的强调文字和图标（琥珀直接放在白底上对比度不足，必须压暗） |
| `accent-soft` | `oklch(0.95 0.045 80)` | `oklch(0.32 0.06 72)` | 选中行、浅色徽标的底色 |
| `on-accent` | `oklch(0.22 0.04 65)` | 同左 | 琥珀填充上的文字（深色字，不用白字） |
| `warn` | `oklch(0.62 0.17 30)` | `oklch(0.72 0.15 32)` | 珊瑚红：失败和警告。琥珀已作为品牌色，不再表示警告 |
| `ok` | `oklch(0.56 0.11 155)` | `oklch(0.74 0.12 155)` | 连接成功 |
| `bg` / `surface` / `elevated` | `0.99` / `0.965` / `1.0`（L，色相 75） | `0.16` / `0.20` / `0.24`（L，色相 70） | 扩展页面的三层表面 |
| `border` | `oklch(0.9 0.008 75)` | `oklch(0.31 0.01 70)` | 1px 分隔 |
| `text` / `muted` | `oklch(0.22 0.012 70)` / `oklch(0.5 0.012 70)` | `oklch(0.94 0.008 80)` / `oklch(0.7 0.012 75)` | 正文与次要文字 |
| `isle` / `isle-2` / `isle-line` | `0.20` / `0.29` / `0.33`（L，色相 70） | `0.25` / `0.33` / `0.40` | 灵岛、划词卡片、指令台的材质 |

- **暗色网页上的灵岛**：采用「深岛 + 细描边」，深岛比宿主背景亮一档，外加一圈 1px 浅描边。这样灵岛在任何网页上都是同一个深色物体，品牌一致，琥珀也始终亮在深底上，最好看。备选的「反色浅岛」不采用。如果真实网页上出现辨识度问题，再重新评估。
- **组件只引用 token**：颜色、字号、控件高度、圆角、缓动和时长都来自 `src/styles/tokens.css`，组件样式不写死这些值。例外只有元素自身的几何尺寸（状态小点、进度细线），以及单个组件独有的一次性动画时长。新增一档尺寸时先加 token，再在组件里使用。
- **不用浏览器原生下拉**：凡是下拉选择，一律用自研的下拉组件（2026-11-14 用户要求），外观和动效与灵岛的生长语言一致。
- **对比度要求**：实现时用脚本校验 token 组合：正文 ≥ 4.5:1，控件与焦点环 ≥ 3:1，`on-accent` 落在 `accent` 上 ≥ 4.5:1。不达标的组合必须调整，不能放行。

### 扩展图标：暗岛微光 · 倒影（2026-11-18，改名为「译屿 / Islet Translate」时定稿）

- 暖黑圆角方块上，暖白横线是原文，下方琥珀胶囊是译文，也就是页面上的灵岛；胶囊下方一到两道淡琥珀倒影（16px 透明度 0.45，32/48px 约 0.3，128px 再加一道 0.14），寓意暗海上发微光的小岛。
- 候选过穹顶、双峰、钟形山体和「琥珀圆点 + 短线」：16px 下分别会被读成日出日落、云、「弹出」按钮和列表项，且与界面里「胶囊即岛」脱节，均不采用（Design 原型「改名 · 译屿图标」页有定稿与各尺寸效果；Fable 5.2 参与决策）。
- 约束：16/32/48 按像素网格单独绘制，128 按商店版式；工具栏状态圆点叠在 16/32 右下角并抠出透明环，倒影与抠除区至少留 1px。几何数据只在 `scripts/build-icons.mjs`，`npm run build:icons` 生成 `public/icon/*.png`、`docs/assets/icon/icon-*.svg` 和无边距主图 `icon.svg`。
- 设置页左上角品牌位：48px 图以 24px 显示（2 倍屏逐像素），名称跟随界面语言（译屿 / Islet Translate）。

**M2b 落地状态（2026-11-16）**：小点、竖排灵岛、弹簧形变引擎、碰撞避让，以及左、右、底部三种停靠已在 M2b PR2 实现，见 `docs/plans/m2b-lazy-runtime-and-isle.md` 第 9 节。与本文的两处偏差：
- 第 2 节第 10 条「灵岛展开后焦点进入灵岛内部」：M2 没有让键盘进入灵岛的入口（指令台在 M3），灵岛按钮不进入网页的 Tab 顺序，键盘用户用面板和快捷键；留到 M3 随指令台补齐。
- 第 3 节「外语页面显示小点」开关：违背「被唤起之前零痕迹」的默认值，也没有人提出需要，暂不提供。
